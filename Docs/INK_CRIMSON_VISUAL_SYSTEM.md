# FLESHDRIVE – Ink-Crimson visual system

## Current implementation

The game now has one authoritative visual contract instead of separate menu,
HUD and arena palettes.

- `InkCrimsonPalette` owns the ten colors and semantic role names.
- `InkCrimsonVisualSystem` restyles local Control overrides and renders a final
  full-screen nearest-color pass above gameplay, HUD, menus and post-process.
- `ink_crimson_quantize.gdshader` forces every final pixel to one of the ten
  opaque master colors. Imported legacy art can therefore remain functional
  while source assets are redrawn incrementally.
- `fleshdrive_theme.tres` defines crisp, square, shadowless reusable controls.
- The main menu has an original procedural pixel biomechanical backdrop and a
  reusable two-tone 12x12 icon family.
- Gameplay VFX use nearest filtering and hard three-band crimson or blue ramps.
  Soft radial flash lights, bloom and chromatic blur are disabled.
- The release gate includes a visual-system contract test.

The repository contains 28 active scenes, 4 shaders, 111 upgrade resources and
1025 PNG files including licensed/source packs. The source library is not the
shipping visual language: the final-frame palette gate is authoritative, while
only referenced assets should be redrawn into the native style.

## Master palette and roles

| Hex | Role | Use |
| --- | --- | --- |
| `#09010d` | Void | clear color, deepest arena mass, sprite cutout shadow |
| `#17001d` | Ink | primary background, inactive areas, large menu fields |
| `#270022` | Panel | cards, HUD plates, floor structure |
| `#450327` | Flesh shadow | organic outline, disabled flesh state |
| `#660f31` | Flesh deep | enemy body midtone, wounds, danger backing |
| `#9c173b` | Flesh | organic foreground, enemy/organ emphasis |
| `#ff0546` | Alert | damage, boss threat, critical warning, selection error |
| `#1e579c` | Tech deep | inactive tech border, electrical shadow |
| `#0098db` | Tech | XP, interaction, active system state |
| `#0ce6f2` | Tech bright | readable text, focus, lightning core, confirmation |

Usage target by visible area: 70% void/ink/panel, 15% crimson ramp, 12% blue
ramp, at most 3% alert or tech-bright peaks. `#ff0546` and `#0ce6f2` must stay
rare enough to retain meaning.

Do not encode a gameplay state by hue alone. Hostile shapes point inward or use
broken/spiked contours; helpful tech uses square nodes, parallel traces and
outward pulses. Text and icons therefore remain distinguishable without color.

## UI style guide

### Grid and scale

- Layout grid: 8 px; micro-alignment: 2 px.
- Body text: 16–18 px Pixeloid Sans; compact metadata: 12–14 px Mono.
- Section heading: 22–30 px; major screen title: 46–70 px.
- Standard button: 56–70 px high, minimum 300 px wide in menus.
- Compact button: 40 px high. Card padding: 16 px. Modal padding: 24–32 px.
- Borders: 2 px normal, 3 px panel emphasis, 4–5 px active left rail.
- Corners: square. Shadows: hard 3x3 px void offset only; no soft shadow.

### Component states

| Component | Idle | Hover/focus | Pressed | Disabled |
| --- | --- | --- | --- | --- |
| Button | panel + tech-deep border | ink + bright-cyan 5 px rail | tech-deep + bright core | ink + flesh-shadow |
| Card | ink + 2 px role border | panel + 3 px role border | same plus 2 px inward shift | ink + flesh-shadow mark |
| Tab | panel + flesh-shadow underline | tech-deep + cyan underline | tech-deep | — |
| Slider | void track + tech fill | bright-cyan fill | bright-cyan square grabber | flesh-shadow |
| Progress | void well + 2 px border | discrete tech or crimson fill | no gradient | — |
| Tooltip | void + 3 px cyan left rail | — | — | — |
| Modal | ink field + panel blocks | selected action gets cyan; destructive gets alert | — | — |

Interaction motion is short and spatial: 60 ms press, 140 ms hover, 220 ms
modal entrance. Scale/offset are allowed; continuous blur, glow and transparent
fades are not part of the art language. The final quantizer also hardens any
legacy transition still using interpolation.

### Icons

Icons use a 12x12 or 16x16 source grid, one-pixel interior details and exactly
two visible colors. Blue icons mean navigation/system/energy. Crimson icons mean
organs, danger, irreversible action or enemy state. Menu icons are generated by
`InkCrimsonIconFactory`; the same silhouettes should be used at 1x or 2x only.

## Screen-by-screen direction

### Startup and loading

Use a void field, one crimson biological trace and one cyan diagnostic trace.
Progress is a discrete cyan block bar; status copy is mono, left aligned. Avoid
full-screen illustration behind loading text.

### Main menu

Implemented: sparse 96 px lab grid, right-side organic mass, orthogonal tech
trace, strong left control column, two-tone action icons. Keep the bright title
and active button as the only simultaneous cyan peaks.

### Settings

One centered panel, section labels in alert crimson, values in cyan. Sliders are
stepped-looking and square. Settings that contradict the visual contract
(bloom/chromatic blur) remain storage-compatible but render as zero under the
strict art direction.

### Progression and skill tree

Use a dark node field with blue connective traces for available paths, flesh
deep for locked biological growth, cyan for selected nodes and alert for
requirements not met. Preserve full descriptions in a fixed right inspector;
do not place prose inside the node graph.

### Run-start scope

The public playtest has no arena selector. Dusk Garden is the single authored
combat site and Voltaic Heart is the single playable Fleshdrive. Prototype
content must not imply that additional arenas are part of this release.

### Gameplay HUD

Keep the existing information architecture but use: HP crimson, XP blue,
Kinetic Charge cyan with alert only at overcharge, boss HP crimson with a
spiked frame. Timer stays isolated at the upper right. Currency and organ type
use a 16 px icon plus a mono number. No widget may use a soft backdrop.

### Level-up cards and organ operation

Cards have a 3 px affinity rail, organ type label above the title, current rank,
and a concrete `NEXT LEVEL` delta block. Illustration occupies at most 32% of a
card. Until every illustration is redrawn, the strict output pass converts the
legacy source while text and hierarchy stay stable.

### Pause, game over, victory and recap

Pause is a compact void panel over a palette-quantized frozen frame. Defeat uses
crimson title and cyan actionable controls; victory reverses those accents.
Recap is a two-column table with mono values, not a decorative poster.

when the frame count is small. Scale assets by integer factors and keep nearest
filtering plus pixel snapping enabled.

2. Hostile/player projectiles, damage/status icons and six most frequent VFX.
3. HUD portrait, HP/XP/charge widgets and crosshair.
4. Organ type icons and the visible offer-card set, grouped by build family.
5. Dusk Garden floor, boundary and props.
6. Splash, loading, operation and recap illustrations.
7. Rare VFX and inactive/prototype content.

Every replacement should be tested at native gameplay zoom before a 4x art
preview. A beautiful zoomed sprite that loses its silhouette at 1x fails review.

## Folder and naming convention

```text
Assets/ink_crimson/
  characters/{koda,crawler,spitter,warden}/
  environments/dusk_garden/
  ui/{icons,cards,frames,cursors}/
  vfx/{electric,flesh,fire,kinetic,status}/
  source/                 # editable source only; not referenced at runtime
Resources/Themes/
Shaders/
Scripts/visual/
```

Runtime files use `ic_<family>_<purpose>_<state>_<size>`, for example
`ic_ui_organ_heart_active_16.png`, `ic_vfx_electric_chain_32.png`, and
`ic_prop_dusk_tree_broken_64.png`. Animation frames stay in one atlas whenever
possible; do not use numbered loose files for newly authored shipping art.

## Consistency gate

Before merging visual work:

1. Run `Tools/run_release_gate.ps1` with the Godot 4.7 console path.
2. Confirm `INK CRIMSON VISUAL SYSTEM TEST PASSED`.
3. Inspect main menu, level-up offer, organ operation, crowded combat and run-end
   at 1280x720 and 1920x1080.
4. Verify no blur/linear filtering, no fractional sprite scale and no HUD overlap.
5. Capture a frame and count colors after composition: only the ten master RGB
   values may be present.

The final output shader is a guardrail, not permission to add arbitrary new
source colors. New art should use the palette natively so semantic roles remain
intentional instead of depending on nearest-color conversion.
